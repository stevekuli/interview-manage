## 三、优先修复的问题

### R1：无 AI 配置时不能正常录入岗位描述（高）

- 证据：`apps/web/src/features/applications/components/application-form-sheet.tsx:108` 根据已测试的服务商决定 `aiEnabled`，`:214` 将整个岗位描述输入区放在条件内。
- 影响：没有配置 Key 的用户连手动保存 JD 都找不到入口；稍后配置模型，也缺少之前收集的原始岗位要求。
- 建议：岗位描述始终可录入；仅“智能提取”依赖模型。未配置时提供“配置 AI”入口，同时允许直接保存。
- 验收：无服务商、服务商失败和可用服务商三种状态均能录入并重新打开 JD；只对智能操作作条件限制。
- 证据等级：源码确认，页面待复现。

### R2：列表请求失败被显示为空数据（高）

- 证据：`apps/web/src/routes/dashboard/applications/index.tsx:92` 只读取 `data/isPending`；`:121`—`:155` 在没有数据且非 pending 时显示 EmptyState，没有独立错误分支。
- 影响：首次请求失败时，已有岗位可能被表现为“还没有岗位”，用户会误以为数据丢失。
- 建议：区分加载、真实空列表、失败、筛选无结果四种状态；失败显示“暂时无法加载岗位”和“重试”。有缓存时保留旧数据并提示更新失败。
- 验收：断网和接口失败不显示首次使用空状态；恢复网络后重试成功，筛选状态保留。
- 证据等级：源码确认，故障注入待验证。

### R3：自动提取可能覆盖用户刚修改的内容（高）

- 证据：`application-form-sheet.tsx:150`—`:157` 将结果中非空的公司、岗位、地点和薪资直接写回当前表单；`:239` 粘贴即触发请求；没有输入版本或字段修改检查。
- 影响：粘贴后手动修正公司名称，较晚返回的 AI 结果仍会覆盖修正；请求期间切换 JD 或编辑目标也缺乏明确的过期结果保护。
- 建议：绑定表单目标与输入版本；只自动填充尚未修改的字段，其余展示待接受建议。新输入使旧请求结果失效。明确提示何时会调用 AI。
- 验收：延迟返回、先粘贴后手动修改、切换岗位和关闭再打开等情况下，旧结果不能覆盖新内容。
- 证据等级：源码风险，未调用模型制造竞态。

### R4：修改岗位或关联简历后，旧匹配分数不失效（高）

- 证据：`packages/api/src/features/applications/service.ts:290`—`:331` 更新 JD/关联简历时未清理匹配分数；`application-ai-copilot.tsx:145`—`:205` 继续显示 `application.matchScore`。
- 影响：新 JD 或另一份简历仍展示上一次评分，用户无法判断分数对应哪份内容。
- 建议：短期在相关输入变化时标记评分过期或清空；长期保存简历版本、JD 版本和评分时间，服务端拒绝过期任务覆盖当前结果。
- 验收：修改 JD、更换简历、评分进行中修改输入后，旧分数不得以有效结果展示。
- 证据等级：源码确认，数据库流程未运行。

### R5：AI 操作缺少统一的配置与下一步引导（中）

- 证据：`application-ai-copilot.tsx` 未读取服务商可用状态；求职信与跟进草拟按钮主要按 pending 禁用。`packages/api/src/features/applications/ai.ts:19`—`:24` 才在请求时返回没有模型配置的错误。
- 影响：用户先点击再遇到失败；岗位表单隐藏 JD，详情却提示“编辑并粘贴岗位描述”，无 Key 场景容易形成死路。
- 建议：显示三个前置状态“关联简历 / 补充岗位描述 / 配置 AI”，每项提供可点击操作。模型设置直接叫“AI 模型”，不要让用户猜“高级 → 集成”。
- 验收：缺少任一条件都能直接前往补齐，返回时岗位和输入保留；条件齐全后才发起模型请求。
- 证据等级：源码确认，实际反馈待复现。

### R6：表单标签未关联输入控件（中）

- 证据：`application-form-sheet.tsx:401`—`:409` 的 Field 将 Label 与输入并列，未传 `htmlFor`；公司与岗位 Input 未设置对应 id 或可访问名称。公共 Label 组件仅渲染原生 label。
- 影响：点击字段名不能可靠聚焦；辅助阅读工具难以识别输入含义。必填信息目前主要依赖视觉星号和禁用按钮。
- 建议：使用现有表单组件或 `useId` 绑定标签与输入，补充 `required/aria-required` 与字段级错误；回车提交使用标准表单语义。
- 验收：按标签能找到并聚焦公司/岗位输入；键盘完成填写与提交；错误与对应字段关联。
- 证据等级：源码确认；不据此声明整站无障碍合规或不合规。

### R7：中文页面仍有英文阶段和面试类型（中）

- 证据：`packages/schema/src/applications/data.ts:11`—`:18` 为 Saved/Applied/Screening 等固定英文；`board.tsx:122` 直接显示 `stage.label`。`interview-dialog.tsx:210` 直接显示英文面试类型。
- 影响：核心看板与周边中文界面不一致；“Screening”也没有直接对应用户熟悉的筛选、笔试等语境。
- 建议：枚举值保持不变，在前端建立统一翻译映射，所有看板、筛选、表单、时间线与统计复用。笔试是否新增状态由原 P5 决策处理，不借翻译偷偷修改数据库枚举。
- 验收：切换中文/英文后所有阶段与面试类型一致变化，历史记录和 API 值不变。
- 证据等级：源码确认，页面待复现。

## 四、交互改善建议

### U1：添加岗位分成核心信息与补充信息

当前表单包含公司、岗位、地点、薪资、来源、阶段、日期、简历、求职信、标签、跟进与备注。建议默认只显示“岗位描述、公司、岗位”，其余折叠为补充信息；保存后提示“关联简历”。

`application-form-sheet.tsx:343` 在无简历时只显示“No resumes yet”。建议提供“创建/导入简历”，携带返回岗位的上下文；先保存草稿，避免切页丢失。此建议需登录态确认实际布局后再定稿。

### U2：侧栏真正收起高级功能

`dashboard/-components/sidebar.tsx:194`—`:231` 只是将现有入口分成四组，工具、设置和高级仍全部展开。建议主导航保持岗位、简历，设置合并；高级默认折叠。保留原路由与功能。

### U3：手机默认采用列表，突出今天需要做的事

`applications/index.tsx:51` 默认 board；`board.tsx:79` 和 `:119` 使用横向滚动及固定宽度列。建议移动端默认列表或阶段分段切换，详情页保留直接修改状态的入口；桌面保留看板。加入“今天面试、待跟进、临近截止”汇总时复用既有日历和跟进数据，不另建重复任务系统。当前仅为源码推导的建议，尚未完成移动端实测。

### U4：生成后先看差异，再接受或打开副本

当前 `applications/ai.ts:253`—`:267` 直接创建副本、重新关联岗位并写时间线。建议先给差异预览和明确接受入口；至少在现阶段提供“打开新简历”和保留原关联的反馈。完整版本绑定、幂等和事实保护仍按原 P4 实施。

### U5：首页与 ATS 使用同一套导航

本轮截图中，首页显示产品名和“进入工作区”；ATS 页使用仅图标品牌及语言、主题、箭头入口，用户跨页后需要重新识别导航。建议共用页头，保留文字“进入工作区”，把 ATS 面向用户的名称改成更直接的“简历可读性检查”。这属于一致性改善，不是功能故障。

首页 AI 说明仍使用“生成岗位定制副本”，未在此处说明仅重写简介；建议直接补上能力边界。页脚仍链接原仓库 LICENSE；如要进一步收敛展示，可改成本地第三方许可说明入口，保留原许可全文，不删除声明。
